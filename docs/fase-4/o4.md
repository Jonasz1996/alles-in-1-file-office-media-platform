# O4 — Nieuw document

Een leeg docx, xlsx of pptx maken in de map die open staat, en het meteen openen in de editor.
De lege bestanden maakt de app zelf (alleen `zipfile`), niet uit de sjablonen van DS.
Bouwontwerp: §2 O4, Keuze 24, 28 en 33, en uit de spike A17 en A22. Zonder office-instellingen
is alles precies fase 3.

## Wat er is

### API

- **`api/app/office/blank.py`** (vervangt de stub van O0, met dezelfde handtekening uit §3.3):
  `blank(kind, locale) -> bytes`. Daarnaast `language(locale)` en `default_name(kind, locale)`.
  - **De taal:** een locale die met `en` begint, is Engels; al het andere (ook geen locale) is
    Nederlands.
  - **docx** (±2,0 KB):
    - `word/document.xml`: één lege alinea, A4 (11906×16838 twips), marges 1440 en kop- en
      voettekst op 708;
    - `word/styles.xml`: `docDefaults` met `w:lang` (`nl-NL` of `en-GB`) en de stijl Normal;
    - `word/settings.xml`: `compatibilityMode` 15 (A17, spike stap 8) en `defaultTabStop` 708.
  - **xlsx** (±1,9 KB):
    - één blad, "Blad1" of "Sheet1", met een lege `sheetData`;
    - een minimale `xl/styles.xml` (één lettertype, twee vullingen, één rand, één celstijl).
  - **pptx** (±4,5 KB):
    - 16:9 (12192000×6858000 EMU) en een staande notitiepagina;
    - één `slideMaster` en één `slideLayout` (type `title`);
    - één dia met een titelvak, met de taal in `endParaRPr`;
    - `ppt/theme/theme1.xml`: 12 kleuren, Calibri Light en Calibri, en een `fmtScheme` met drie
      van elk (het minimum dat de spec vraagt).
  - **Deterministisch:**
    - elk onderdeel heeft `date_time` (1980, 1, 1, 0, 0, 0), `create_system` 3 en de rechten
      0644;
    - de volgorde ligt vast, met `[Content_Types].xml` voorop.

    Zo is er één blob per soort en taal, hoeveel lege documenten er ook zijn. `_build` onthoudt
    de bytes per soort en taal (`functools.cache`).
- **`api/app/routers/office_new.py`**: `POST /api/v1/office/new` met
  `{parent_id, kind, name?}` geeft 201 met de `NodeOut` van het nieuwe bestand.
  - **Het bestand:** gewoon een bestand. De bytes gaan eerst als tijdelijk bestand met hun sha
    door `BlobStore.receive`, dan zet `place_file(..., conflict="rename", actor=user)` ze op hun
    plek. Daarmee gelden de rechten, het quotum, de gebeurtenissen (`files.changed`) en de
    sloten van een upload. Er gaat niets naar DS; daarom werkt het ook als DS weg is
    (Keuze 28). Omdat `actor` de ingelogde gebruiker is, is `pdf_state` niet `ask`, en zet O3
    het voorbeeld en de PDF vanzelf klaar.
  - **Gedeelde map met schrijfrecht:** het bestand wordt van de eigenaar van de map en kost zijn
    quotum (B18). De `guard` is `writable(user, map)`, zoals bij een upload.
  - **De naam:**
    - zonder naam: "Nieuw document.docx", "Nieuw werkblad.xlsx" of "Nieuwe presentatie.pptx",
      in het Engels "New document.docx", "New spreadsheet.xlsx" en "New presentation.pptx";
    - de taal is `user.locale`, en zonder keuze de eerste taal van `Accept-Language`, zoals de
      web-app zijn taal kiest (`nl*` is Nederlands, een andere taal Engels, niets of `*`
      Nederlands);
    - een gegeven naam gaat door `clean_name`. Eindigt hij niet op de extensie van de soort, dan
      komt die erbij; is hij dan te lang, dan wordt de stam korter;
    - bestaat de naam al (zonder op hoofdletters te letten), dan kiest `place_file` onder het
      slot van de eigenaar de vrije naam: "Nieuw document (1).docx", dan (2), enzovoort.
  - **Fouten** (elk via `errors.fail`, met een code uit `web/src/i18n/errors/*.ts`):

    | Status | Code | Wanneer |
    |---|---|---|
    | 401 | | niet ingelogd |
    | 403 | `read_only` | alleen leesrecht op de map |
    | 404 | `folder_not_found` | geen map, niet zichtbaar, in de prullenbak (ook een map erboven) of een bestand |
    | 413 | `no_room` / `no_room_owner` | het eigen quotum, of dat van de eigenaar van de gedeelde map, is vol |
    | 422 | `album` | de map is een album |
    | 422 | `invalid_name` / `invalid_input` | een naam die niet mag (`/`, `..`, een tab) of te lang is, of een andere soort |
    | 503 | `office_off` | office is niet ingesteld, of de beheerder zette het uit |

### Web

- **`web/src/office/newItems.ts`** (vervangt de stub van O0, met dezelfde vorm).
  - **Wanneer er items zijn:** alleen als `status.editing` waar is, en alleen voor de soorten
    in `status.new_kinds`, in de vaste volgorde docx, xlsx, pptx. Anders geen items, en dan
    toont `Files.tsx` (O0) de knop "Nieuwe map" van fase 3. `Files.tsx` vraagt de items alleen
    voor een map waar je mag schrijven.
  - **Een item kiezen:**
    - `POST /office/new` zonder naam: de server kiest hem in jouw taal;
    - het bestand komt in de lijst (`added`), een schermlezer hoort "<naam> gemaakt";
    - dan gaat de app naar `/bewerken/<id>` (`openEditor`, O2). Sluiten in de editor gaat terug
      naar de map.
  - **Een fout** (quotum vol, de map is weg, alleen leesrecht) wordt een foutmelding; je blijft
    in de map.
  - **Twee keer snel kiezen** in dezelfde map maakt er één: per map loopt er hooguit één.
- **Het menu zelf** (de knop Nieuw, de sneltoets O en het submenu Nieuw in het menu van de map)
  is de haak van O0 in `Files.tsx`. De teksten staan in het bevroren blok `office` van
  `browser.*`. O4 voegt geen tekst toe.
- **Toetsenbord:** zie `docs/fase-4/toetsenbord-o4.md`.

## Afwijkingen (en waarom)

1. **Een naam die al bestaat, wordt "(1)", niet "(2)".** Het ontwerp geeft als voorbeeld
   "Nieuw document (2).docx". `place_file` met `rename` kiest de vrije naam met `free_name`,
   onder het slot van de eigenaar. Dat doet de app ook bij uploaden, kopiëren en terugzetten, en
   die nummering begint bij (1). Eén manier van nummeren in de hele app is veiliger dan een eigen
   telling naast het slot.
2. **503 `office_off` zonder office-instellingen of met office uit.** Het ontwerp noemt geen 503.
   Maar zonder office moet de app precies fase 3 zijn, en dan hoort er ook via de API geen nieuw
   document te zijn. Met DS weg, nog aan het starten of verkeerd ingesteld werkt het wel
   (Keuze 28).
3. **Elke naam eindigt op de extensie van de soort.** Het ontwerp zegt "een naam zonder extensie
   krijgt die erbij". Hier krijgt elke naam die niet op `.docx`, `.xlsx` of `.pptx` (van de
   gekozen soort) eindigt, die extensie erbij, dus ook "plan.docx" bij een pptx
   ("plan.docx.pptx"). Zo past de naam altijd bij de inhoud: de editor, de invoercontrole en de
   PDF kijken naar de extensie. Een te lange naam krijgt een kortere stam, zodat de extensie
   blijft.
4. **De taal zonder `user.locale` komt uit `Accept-Language`.** Het ontwerp noemt alleen
   `user.locale`. Zonder eigen keuze toont de web-app de taal van de browser; de naam volgt dan
   wat de gebruiker ziet. Geen van beide: Nederlands.
5. **Elke reden waarom de map er niet is, geeft 404 `folder_not_found`**: een bestand als map, een
   map in de prullenbak (ook via een map erboven), een map van een ander die niet gedeeld is. Het
   ontwerp noemt alleen de code. Eén code verraadt niet of er iets is.
6. **Meer onderdelen dan Keuze 24 noemt:** `word/settings.xml` (A17), de stijl Normal in de
   docx, de notitiepagina en de `fmtScheme` in de pptx, en de taal in de dia. Dat is het minimum
   waarmee de echte DS alle drie opent zonder melding (gemeten in de e2e).
7. **De web-app geeft geen naam mee** (het veld `name` is er wel in de API). Het ontwerp vraagt
   geen naamvenster, en de editor kan het bestand niet hernoemen. Hernoemen kan daarna in
   Bestanden, zoals altijd.
8. **Status 4 in de test met de echte DS** wordt bewezen met de rij in de database
   (`office_session.closed_reason` is `no_changes`; alleen lezen). Met de echte DS is er geen log
   van de callbacks, en geen API die de reden geeft. Met de nep-DS staat de callback met status 4
   in de log van de nep-DS.
9. **De controle op A17 is getoetst met een tegenvoorbeeld:** een tijdelijke test (niet in het
   repo) uploadde dezelfde docx zonder `word/settings.xml`. Daar faalde de controle zoals
   verwacht (de editor toonde de melding met OK).

Geen hotfixes van O0 nodig.

## Testen

```sh
# API
cd api && uv run pytest -q -p no:cacheprovider tests/test_office_blank.py tests/test_office_new.py
# Web
cd web && npx vitest run src/office/newItems.test.ts
# e2e met de nep-DS (na npm run build)
cd api && uv run --with playwright pytest ../e2e/test_office_o4.py -m office -q -p no:cacheprovider
# e2e met de echte DS (eigen container, zie docs/fase-4/e2e.md)
OFFICE_DS_NAME=o4-ds OFFICE_DS_PORT=18094 OFFICE_DS_DIR=<map> bash e2e/office_ds.sh start
OFFICE_DS_NAME=o4-ds OFFICE_DS_PORT=18094 OFFICE_DS_DIR=<map> bash e2e/office_ds.sh wait
cd api && E2E_REAL_DS=http://127.0.0.1:18094 E2E_REAL_DS_SECRET_FILE=<map>/jwt.secret \
  uv run --with playwright pytest ../e2e/test_office_o4_real.py -m office_real -q -p no:cacheprovider -s
OFFICE_DS_NAME=o4-ds OFFICE_DS_PORT=18094 OFFICE_DS_DIR=<map> bash e2e/office_ds.sh stop
```

Gemeten met de echte DS (twee runs): alle drie openen zonder opnieuw te laden. De PDF is er 2,3
tot 3,9 s na het maken, met één pagina. "Downloaden als docx" geeft een docx zonder melding.

**Klaar als:**

- **De drie soorten openen in de echte DS en zetten om naar PDF:**
  `test_office_o4_real.py::test_nieuw_openen_sluiten_en_omzetten_echt[docx|xlsx|pptx]`.
- **Het menu werkt met het toetsenbord:**
  `test_office_o4.py::test_nieuw_document_met_alleen_het_toetsenbord` en
  `::test_nieuw_via_het_contextmenu_van_de_map`.

- **`docs/fase-4/toetsenbord-o0.md`** heeft nog het open punt "O (het menu Nieuw) met alleen het
  toetsenbord: pas als `office/newItems.ts` items geeft (O4)". Dat is nu gedaan (zie

- **§2 O4 van het bouwontwerp** geeft "Nieuw document (2).docx" als voorbeeld; de app geeft (1)
  (afwijking 1). Bij het samenvoegen de tekst van het ontwerp gelijktrekken.
- **Met DS weg werkt de API, maar toont de web-app het menu niet** (zoals §2 O4 vraagt: alleen
  als `status.editing`). Wie een nieuw document wil terwijl de editor weg is, kan het dus niet in
  de web-app maken. Dat lijkt goed: openen zou dan toch niet lukken.
